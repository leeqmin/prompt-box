# 문항 프롬프트 저장소 — 설계

작성일: 2026-10-26

## 1. 목적
문항을 만들 때 쓰는 프롬프트를 각자 보관하고 꺼내 쓰는 **개인용 앱**이다.
프롬프트마다 그 프롬프트로 만든 결과 문항(최대 3개)과 좋았던 점·나빴던 점을 함께 남긴다.
같은 앱을 동료에게 링크로 나눠 주면, 각자 자기 기기에서 자기 데이터만 쓴다.

## 2. 지키는 조건
- **데이터는 각 기기 안에만 저장한다.** 서버로 아무것도 보내지 않는다. 분석 도구나 외부 요청도 없다.
- **코드, 문서, 화면에 회사 이름, 특정 사이트 이름이나 주소를 넣지 않는다.** 처음 실행했을 때 데이터는 비어 있다.
- **외부 서비스로 자동 전송하거나 다른 사이트와 연결하는 기능은 없다.** 사용자가 직접 복사해서 쓴다.
- 설치 없이 쓴다. 노트북 브라우저와 폰 브라우저 모두 지원하고, "홈 화면에 추가" 또는 "앱 설치"(PWA)로 앱처럼 쓸 수 있다.
- 화면 문구는 한국어로 한다.

## 3. 기술 구성
- 순수 HTML, CSS, JavaScript. 빌드 과정과 프레임워크는 쓰지 않는다. ES 모듈을 쓴다.
- 저장: IndexedDB.
- 수식: KaTeX와 auto-render. 저장소에 파일을 같이 넣는다(vendor). CDN에 의존하지 않고, 오프라인에서도 동작해야 한다.
- 배포: GitHub Pages (공개 저장소). 경로가 `/<저장소이름>/`이므로 모든 경로는 상대 경로로 쓴다.
- PWA: `manifest.webmanifest`, 서비스 워커(앱 파일 캐시, 새 버전 알림).
- 대상 브라우저: 최신 Chrome, Edge, Safari(iOS 포함).

## 4. 데이터 구조

### 4.1 prompts 저장소 (키: id)
| 필드 | 형식 | 설명 |
|---|---|---|
| id | 문자열 (UUID) | |
| title | 문자열 | 필수 |
| subject | 문자열 | 과목 (자유 입력, 기존 값 자동완성) |
| unit | 문자열 | 단원 (자유 입력, 자동완성) |
| format | 문자열 | 형식 (예: A형, B형 — 자유 입력, 자동완성) |
| tags | 문자열 배열 | |
| detail | 1~5 정수 또는 null | 자세함 정도 (1 대략적인 지시 ~ 5 아주 구체적인 지시) |
| verdict | 'good' / 'bad' / 'undecided' | 판정, 기본 'undecided' |
| body | 문자열 | 프롬프트 본문 |
| memo | 문자열 | 언제 쓰면 좋은지 등 |
| results | 배열 (최대 3) | 4.2 참고 |
| sourceId | 문자열 또는 null | 복제 원본 프롬프트 id |
| createdAt, updatedAt | 숫자 (ms) | |

### 4.2 결과 문항 (prompts.results의 원소)
| 필드 | 형식 | 설명 |
|---|---|---|
| id | 문자열 (UUID) | |
| text | 문자열 | 문항 텍스트. `$…$`, `$$…$$`, `\(…\)`, `\[…\]` 수식을 KaTeX로 표시 |
| imageIds | 문자열 배열 | images 저장소의 id |
| rating | 'good' / 'bad' / null | |
| reason | 문자열 | 좋았던·나빴던 이유 |
| date | 'YYYY-MM-DD' | 기본값은 추가한 날 |
| note | 문자열 | 문항 ID나 기타 메모 |

### 4.3 images 저장소 (키: id)
- `{ id, blob (JPEG), width, height, createdAt }`
- 저장 전에 긴 변을 최대 1600px로 줄이고 JPEG 품질 0.85로 다시 인코딩한다. 원본이 더 작으면 크기는 그대로 두고 JPEG로만 바꾼다.
- 결과 문항이나 프롬프트를 지우면 연결된 사진도 지운다. 시작할 때 어디에도 연결되지 않은 사진이 있으면 정리한다.

### 4.4 meta 저장소
- `lastBackupAt`, `schemaVersion`(1부터 시작).

## 5. 화면

### 5.1 목록
- 탭: **전체 / 좋은 프롬프트(verdict=good) / 나쁜 프롬프트(verdict=bad)**
- 검색: 제목, 본문, 메모, 태그, 결과 문항 텍스트·이유에서 찾는다.
- 필터: 과목, 태그, 자세함(1~5).
- 정렬: 최근 수정순(기본), 자세함 높은순, 결과 좋음 많은순.
- 카드에 보여 줄 것: 제목, 과목·단원, 태그, 판정 표시, 자세함, 결과 좋음 ○ / 나쁨 ○, 고친 날짜.
- 넓은 화면(768px 이상)은 목록과 상세를 나란히 보여 준다. 좁은 화면은 목록을 누르면 상세로 넘어가고 뒤로 가기가 된다.
- 주소 해시(`#/p/<id>`, `#/p/<id>/edit`, `#/settings`)로 화면을 구분한다. 브라우저 뒤로 가기가 동작해야 한다.

### 5.2 상세
- 제목, 분류, 태그, 판정, 자세함, 메모를 보여 준다.
- 프롬프트 본문은 줄바꿈을 그대로 보여 주고, 「복사」 버튼을 누르면 "복사됨" 표시가 뜬다.
- 결과 문항 1~3은 각각 접었다 펴는 칸이다.
  - 접힘: "결과 n · 좋음/나쁨 · 날짜 · 이유 첫 줄"
  - 펼침: 문항(수식 표시), 사진(누르면 크게 보기), 평가, 이유, 메모
- 버튼:
  - 「수정」
  - 「복제해서 새 버전으로」: 제목 뒤에 " (v2)"를 붙인다. 이미 (vN)이면 N+1로 바꾼다. 결과 문항은 비우고, verdict는 undecided, sourceId는 원본 id로 둔다.
  - 「삭제」: 확인 창을 띄운다.
- 복제본이면 "○○에서 복제" 링크를 보여 준다.

### 5.3 수정
- 상세와 같은 배치에서 각 칸을 입력칸으로 바꾼다.
- 판정은 세 개 중 하나를 고르는 버튼, 자세함은 1~5 버튼과 "없음"으로 한다.
- 결과 문항: 「결과 추가」(3개면 숨김), 「삭제」. 텍스트 입력 아래에 수식 미리보기를 실시간으로 보여 준다(입력 후 300ms 지연).
- 사진 넣기:
  - 해당 결과 칸에 포커스가 있을 때 Ctrl+V로 클립보드 이미지를 붙여넣는다.
  - 파일 선택(폰은 갤러리·카메라)으로 넣는다.
  - 끌어다 놓기로 넣는다.
  - 사진마다 삭제 버튼을 둔다.
- 「저장」, 「취소」. 바뀐 내용이 있는데 나가려 하면 확인 창을 띄운다(화면 이동과 탭 닫기 모두).
- 제목이 비어 있으면 저장하지 않고 알린다.

### 5.4 설정
- 「백업 파일로 저장」, 「백업 파일 불러오기」
- 저장 공간 사용량 표시(`navigator.storage.estimate()`).
- 마지막 백업 날짜 표시.
- `navigator.storage.persist()`로 영구 저장을 요청한다(첫 저장 때 한 번).
- 앱 버전 표시.

### 5.5 공통
- 마지막 백업 후 14일이 지났거나, 백업한 적이 없는데 프롬프트가 1개 이상이면 상단에 "백업한 지 오래됐어요 · 지금 백업" 띠를 보여 준다.
- 새 서비스 워커가 대기 중이면 "새 버전이 있습니다 · 새로고침" 띠를 보여 준다.
- 폰 화면에서 버튼과 입력칸은 최소 44px 높이로 한다. 시스템 다크 모드를 따른다.

## 6. 백업

### 6.1 저장
- 파일 이름: `prompt-box-backup-YYYY-MM-DD.json`
- 형식:
```json
{ "app": "prompt-box", "schemaVersion": 1, "exportedAt": 0,
  "prompts": [ ... ],
  "images": [ { "id": "", "type": "image/jpeg", "data": "<base64>", "width": 0, "height": 0, "createdAt": 0 } ] }
```
- 저장이 끝나면 `lastBackupAt`을 갱신한다.

### 6.2 불러오기 (합치기)
- 파일 형식을 확인한다(`app`, `schemaVersion`, 필수 필드). 맞지 않으면 아무것도 바꾸지 않고 이유를 보여 준다.
- id 기준으로 합친다.
  - 없는 id는 새로 추가한다.
  - 있는 id는 `updatedAt`이 더 큰 쪽을 남긴다.
- 적용하기 전에 "새로 n개, 덮어씀 n개, 그대로 n개"를 보여 주고 확인을 받는다.
- 사진은 남게 되는 프롬프트에서 쓰이는 것만 넣는다.
- 하나의 트랜잭션으로 처리한다. 중간에 실패하면 아무것도 바뀌지 않는다.

## 7. 오류 처리
- 저장 실패(용량 초과 등): 입력 내용을 지우지 말고 "저장 공간이 부족합니다. 백업 후 사진을 정리해 주세요"를 띄운다.
- IndexedDB를 쓸 수 없는 환경(일부 사생활 보호 모드 등): 시작할 때 "이 브라우저에서는 저장할 수 없습니다"를 표시한다.
- 지원하지 않는 이미지 형식: 해당 파일만 건너뛰고 알린다.
- 수식 문법 오류: 원문을 그대로 빨간색으로 표시한다. KaTeX `throwOnError: false`.

## 8. 파일 구성
```
index.html
manifest.webmanifest
sw.js                 서비스 워커 (캐시 목록, 버전)
css/app.css
js/main.js            시작, 라우팅
js/db.js              IndexedDB 래퍼 (prompts, images, meta)
js/model.js           프롬프트·결과 생성, 복제, 검증, 집계 (순수 함수)
js/images.js          축소·인코딩, 붙여넣기·파일 처리
js/backup.js          내보내기·가져오기·합치기 (합치기 계획은 순수 함수)
js/math.js            KaTeX 표시 래퍼
js/views/list.js, detail.js, edit.js, settings.js
js/ui.js              공통 요소 (확인 창, 띠, 토스트)
vendor/katex/         KaTeX (MIT)
icons/                앱 아이콘 (192, 512, maskable)
tests/                브라우저 테스트 페이지 + Node 단위 테스트
README.md             사용법 (설치, 백업, 폰에서 홈 화면 추가)
```

## 9. 테스트
- **순수 함수 단위 테스트**(Node 내장 `node:test`, 외부 패키지 없음): `model.js`(복제 제목 규칙, 검증, 집계·필터·정렬), `backup.js`(형식 검증, 합치기 계획).
- **브라우저 테스트**(`tests/browser.html`): IndexedDB 저장·삭제와 사진 정리, 백업 저장 → 지우기 → 불러오기 왕복, 사진 축소 크기, KaTeX 표시.
- **화면 확인**: 1280px, 375px 너비에서 목록·상세·수정·설정을 실제로 연다. 붙여넣기, 접기·펴기, 뒤로 가기, 저장 안 한 내용 경고를 확인한다.
- **PWA 확인**: 배포 후 오프라인에서 열리는지, 새 버전 띠가 뜨는지 확인한다.

## 10. 하지 않는 것
- 기기 간 자동 동기화, 계정, 서버 저장
- 여러 사람이 같이 쓰는 공유 저장소
- 외부 사이트 연결, 자동 전송
- 프롬프트 버전 기록 (복제로 대신한다)
